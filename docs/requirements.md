# 要件と決定事項

このファイルが要件の正本。決定には日付と理由を残す。

## ミッション・ビジョン・バリュー
機能の追加・削除や設計で迷ったら、ここに照らして判断する。合わない機能は作らない。

- **ミッション(本人)**: 物理・数学の知識を IT に活かす(2026-11-15 ユーザー決定)
- **ビジョン(本人・10 年後)**: 10 年後の未来も考えられる、思慮深い人間になる(2026-11-15 ユーザーの言葉)
- **このアプリの役割(⚠ 案)**: ミッションとビジョンのために、毎日の予定・やることと、物理・数学・IT が交わる分野の世界の動きを、ひとつの場所で把握できるようにする
- **バリュー**(2026-11-15 ユーザー決定)
  1. 原理から考える(ユーザーは「原理至上主義者」)
  2. 自分の分野との関係を重視する(ニュースに求めるもの)
  3. 品質を優先する(時間・費用・品質がぶつかったら品質。理由: 低品質なものは LLM でいくらでも生成できる)
- **制約**: 費用は生活を圧迫しない範囲に収め、その中で品質を最大化する(2026-11-15 ユーザー確認)

## 機能一覧(初期スコープ)
### ToDo
- タイトル、優先度、期限(任意)、完了フラグ
- 2026-11-16: **詳細(任意)を持つ**(ユーザー提案)。理由: 「牛乳を買う」だけでは目的(シチュー用か飲む用か)が分からないため。改行可。「なし」は空文字で表す(NULL と空文字の 2 通りにしない)。一覧ではタイトルの下に表示
- 2026-11-15: 優先度は **高・中・低** の 3 段階。作成時に必ず指定する(既定値は持たない)
- 2026-11-15: 期限を超過したタスクは、表示で**接頭辞**を付けて示す
- 2026-11-15: 接頭辞は `【超過】-`(ユーザー決定)
- 2026-11-15: 「超過」= 未完了のまま期限の**翌日以降**になっていること。期限当日は超過ではない。完了済みは超過しない
- 2026-11-15: 一覧は**未完了のタスクだけ**を優先度の降順(高→中→低)で表示。同じ優先度では作成日時の古い順(作成日時も同じなら元の順序)
- 2026-11-16: **完了済みタスクは別の「完了済み」一覧で見られ、未完了に戻せる**(ユーザー決定)
- 2026-11-16: 完了済み一覧は**作成日時の新しい順**(ユーザー決定)。同じ作成日時なら元の順序を保つ。完了日時は記録しない(スキーマ変更を避けた)
- 2026-11-16: **編集できるのはタイトル・優先度・期限・詳細**。作成日時は変えない。編集に失敗したらタスクは一切変わらない。編集はポップアップ(JavaScript が動かないときは編集ページ)(ユーザー決定)
- 未決定: 繰り返しタスクを扱うか

### 予定
- タイトル、開始日時、終了日時(任意)、場所・メモ(任意)
- 「今日の予定」を表示
- 2026-11-15: **終日予定を扱う**。期間は開始日〜終了日(終了日を含む)。終了日は任意
- 2026-11-15: 時刻付き予定の**終了は任意**。期間は半開区間 [開始, 終了)。終了なし・終了=開始は「瞬間の予定」で開始日にだけ出る
- 2026-11-15: 日をまたぐ予定は**重なる日すべてに出す**(その日の [0:00, 翌0:00) と期間が重なれば出す。翌0:00 ちょうどに終わる予定は翌日に出ない)
- 2026-11-15: その日の一覧は 終日予定 → 時刻付き予定(開始順)
- 2026-11-15: 終了が開始より前の予定、空タイトルの予定は作れない
- 2026-11-15: 時刻はタイムゾーンなしの日本時間として扱う(利用者 1 人のため)
- 2026-11-15: **繰り返し予定は今は扱わない**(単発が完成してから別ブランチで設計)

### メモ
- タイトル、本文、タグ、作成日時・更新日時
- 2026-11-15: **タイトルは必須**、本文は空でもよい
- 2026-11-15: 作成直後は 更新日時 = 作成日時。編集すると更新日時だけ変わる。作成日時より前の時刻では編集できない。編集に失敗したらメモは一切変わらない
- 2026-11-15: **タグを付ける**(1 メモに複数)。前後の空白は除く・空タグ不可・重複は 1 つにまとめる。英字の大文字小文字は区別する(⚠ 確認待ち)
- 2026-11-15: **キーワード検索**: タイトルか本文に含まれるもの。英字の大文字小文字は区別しない。空のキーワードは全件
- 2026-11-15: 一覧は**更新日時の新しい順**。同じ日時は元の順序を保つ
- 2026-11-15: タグの DB 設計は `tags` + 中間テーブル `memo_tags`(多対多)。`docs/db/er.md` 参照
- 2026-11-16: **メモの画面**(ユーザー決定。見た目は `docs/design/memo/`)
  - 一覧は 2 列のカード(更新日時の新しい順)。上に検索欄とタグの絞り込みボタン、「N まい」の件数
  - **新規作成・編集はポップアップ**(本文が長くても書けるよう大きく取る)。JavaScript が動かないときは専用ページ。削除はポップアップの中(確認つき・物理削除)
  - **タグは空白か「,」「、」で区切って入力**。先頭の # は付けても付けなくてもよい。空白を含むタグは作れない
  - **検索は打つたびに絞り込む**(JavaScript)。JavaScript が動かないときは Enter でサーバー側の検索
  - タグの絞り込みボタンは「すべて」+ メモに付いているタグだけ。付いているメモが多い順、同数なら名前順(付いていないタグは押しても 0 件なので出さない)
- 2026-11-16: **どのメモからも使われなくなったタグも `tags` に残す**(ユーザー決定)。理由: 次にタグを付けるときの候補に出せるようにするため。たまったタグを消す手段は必要になったら別に作る

### ニュースの表示(2026-11-16 ユーザー決定)
- 一覧に出すのは**要約済みの記事だけ**(1 日 30 件の上限で選ばれたもの)
- **要約した日ごと**(新しい日が上)に区切り、日の中は優先順位(両分野 → 片方 → 当たらなくなった記事、同じなら公開日時の新しい順)
  - 要約した日で区切るのは、翌日に回った記事が古い日の段に後から増えないようにするため
  - 一覧では記事を落とさない。キーワードを消して当たらなくなった要約済みの記事は、その日の最後に回す
- **30 件ごとにページを分ける**(1 日の上限と同じ数なので、だいたい 1 ページ = 1 日)
- **既読を管理する**。既読の記事は薄く表示して残す。元記事のリンクを開くと自動で既読になり、「既読」ボタンでもできる。未読に戻せる
  - 自動の既読は、リンクのクリック時に JavaScript が POST を送って行う。GET で既読にしない(ブラウザの先読みで開いていない記事が既読になるのを防ぐ)。JavaScript が動かないときはボタンで

### Web 画面(共通)
- 2026-11-16: **ToDo → 予定 → メモの順に 1 機能ずつ作り、最後に「今日」のまとめ画面**(ユーザー決定)。早く実物で振る舞いを確かめるため。ニュースは PDA とは性質が違うので PDA の画面の後
- 2026-11-16: 順番を変更: **メモ → 予定 → 今日**(ユーザー決定)。メモはドメインと保存が完成済みで、デザインのモックアップもあるため先に作る。メモは「思考の整理」に使う
- 2026-11-16: **「今日」の画面には、予定のうち今日の分を並べる**(ユーザー決定)
- 2026-11-16: 見た目は `docs/design/` のモックアップに合わせる。画面下のタブバー(今日・ToDo・予定・メモ・ニュース)。まだない画面のタブは押せない表示
- 2026-11-16: ~~削除は確認ページを経由する~~ → 同日に変更(下)
- 2026-11-16: **削除はブラウザ標準の確認ポップアップ(`confirm()`)で確かめる**(ユーザー決定。ToDo・予定・メモ共通)。理由: 別ページへ移ると手数が多い。このため JavaScript を最小限使う(確認の 1 か所だけ)。JavaScript が動かない環境では確認なしで削除される(ユーザー了承)
- 2026-11-16: **削除は物理削除**(行を DELETE する。ユーザー決定。ToDo・予定・メモ共通)。消したものはアプリから戻せない。「一覧から外したいが残したい」タスクは「完了」で扱う
- 2026-11-16: **JavaScript は使い勝手のために使ってよい**(ユーザー決定。キーワードの画面の絞り込みから)。ただし JavaScript が動かなくても表示・追加・削除はできるようにする。業務ルールの最終判定(重複など)は必ずサーバー側で行う
  - 確認の文言は `data-confirm` 属性に入れ、共通スクリプトが文字列として読む。`onsubmit` に直接タイトルを埋め込まない(タイトルがコードとして実行されうるため)
- 2026-11-16: 書き込み(POST)の後は一覧へリダイレクトする(Post/Redirect/Get)。再読み込みで二重に登録されるのを防ぐため
- 2026-11-16: DB ファイルは既定で `data/pda.db`。環境変数 `PDA_DB` で変えられる。起動時に `migrate_file` で未適用のマイグレーションを当てる

### ニュース
- 1 日 1 回、設定したフィードから記事を取得
- IT・科学に関係する記事に絞る(ミッションに合わせ、物理・数学と IT が交わる分野を重視する。2026-11-15)
- 記事ごとに日本語要約を作り、配信元・元記事リンクと一緒に表示
- 2026-11-16: **ニュースのビジネスロジックを PDA の画面(予定・メモ)より先に作る**(ユーザー指示。ToDo の画面の後)
- 2026-11-16: **絞り込みはキーワード**(ユーザー決定)。費用 0 円・結果が決定的でテストしやすい。キーワードは `config.py` で変えられる
  - キーワードは「物理・数学」と「IT」の 2 グループ。タイトルか概要文にどちらかのグループの語が 1 つでもあれば対象
  - 英字だけの語は単語単位で照合し、大文字小文字を区別しない(`AI` は `maintain` に当たらない)。それ以外(日本語など)は部分一致
- 2026-11-16: **優先順位は分野の重なり**(ユーザー決定)。当たったグループの数が多い順(両方 > 片方)→ 公開日時の新しい順(公開日時なしは後)。バリュー「自分の分野との関係」をそのまま並び順にする
- 2026-11-16: **1 日に要約する件数の上限は既定 30 件**(`config.py` で変更可)。上限を超えた記事は保存するが要約しない。翌日以降も候補に残る
- 2026-11-16: **対象になった記事だけを保存する**。対象外の記事はキーワードで毎回落とせる(費用 0 円)ので保存しない
- 2026-11-16: **同じ URL の記事は 1 件**。同じ話題の別記事(URL が違う)はまとめない(ユーザー決定。「やらないこと」参照)
- 2026-11-16: **フィードは `config.py` で管理し、最初は空**(ユーザーが後で指定する)。設定から消したフィードの記事は DB に残す
- 2026-11-16: **フィードは Qiita・Zenn(数学・物理系のタグ / トピック)と arXiv(quant-ph・cs.IT・cs.LG)**(ユーザー決定)。Mathlog は RSS がないので外す(「やらないこと」参照)。一覧は `src/pda/config.py` の `FEEDS`
- 2026-11-16: キーワードの画面は**語を横に詰めて並べ、PC ではグループを 2 列に**する。ページネーションはしない(65 語程度で、目的が「登録済みか確かめる・足す・消す」なので、ページを分けると探す手間が増える)。追加の入力欄が絞り込み欄を兼ねる(ユーザー決定)
- 2026-11-16: **キーワードは DB で管理し、Web 画面で追加・削除する**(ユーザー決定)。理由: 使う人が読みながら日常的に育てる値なので、コード(`config.py`)ではなくデータ。英字の大文字小文字だけが違う語は同じ語とみなし、重複登録を断る(照合で同じとみなす語は登録でも同じとみなす)
- 2026-11-16: 記事の URL は `http` / `https` だけを受け付ける。`javascript:` などの URL がリンクになると画面で攻撃コードが動くため
- 2026-11-16: 概要文の HTML タグは取り除いて保存する。「概要文なし」は空文字。公開日時は RSS の UTC を日本時間に直して持つ
- 2026-11-16: モック要約は概要文の先頭 200 文字(`config.py` で変更可)。切ったときは末尾に「…」
- 2026-11-16: 要約器が一部の記事の要約を返さなかったときは、その記事を要約済みにしない(次回の候補に残る)

## 費用方針
- 2026-11-15: 費用は最小に抑える(ユーザーの生活費に響かないこと)。手段はプロンプト・設計の工夫 + モデル選択
- 概算(1 日 30 記事・まとめて 1 リクエスト、1 ドル = 150 円で換算): Opus 5.5 → 月約 600〜1,200 円 / Haiku 5.5 → 月約 15 円 / Haiku 5.5 + Batch API → 月約 8 円
- 2026-11-15: **当面は Claude API を呼ばず、モック要約で進める**(費用 0 円)。モック要約 = RSS の概要文を先頭から一定文字数で切ったもの。本物への切り替えは `config.py` の設定 1 か所で行えるようにする
- 未決定(本物に切り替えるとき決める): 既定モデル(候補: Haiku 5.5)/ 月の上限額(Console の利用上限にも設定する)
