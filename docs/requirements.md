## ミッション・ビジョン・バリュー
機能の追加・削除や設計で迷ったら、ここに照らして判断する。合わない機能は作らない。

- **ミッション(本人)**: 物理・数学の知識を IT に活かす(2026-11-15 ユーザー決定)
- **ビジョン(本人・10 年後)**: 10 年後の未来も考えられる、思慮深い人間になる(2026-11-15 ユーザーの言葉)
- **このアプリの役割(⚠ 案)**: ミッションとビジョンのために、毎日の予定・やることと、物理・数学・IT が交わる分野の世界の動きを、ひとつの場所で把握できるようにする
- **バリュー**(2026-11-15 ユーザー決定)
  1. 原理から考える(ユーザーは「原理至上主義者」)
  2. 自分の分野との関係を重視する(ニュースに求めるもの)
  3. 品質を優先する(時間・費用・品質がぶつかったら品質。理由: 低品質なものは LLM でいくらでも生成できる)
- **制約**: 費用は生活を圧迫しない範囲に収め、その中で品質を最大化する(2026-11-15 ユーザー確認)

## 機能一覧(初期スコープ)
### ToDo
- タイトル、優先度、期限(任意)、完了フラグ
- 2026-11-16: **詳細(任意)を持つ**(ユーザー提案)。理由: 「牛乳を買う」だけでは目的(シチュー用か飲む用か)が分からないため。改行可。「なし」は空文字で表す(NULL と空文字の 2 通りにしない)。一覧ではタイトルの下に表示
- 2026-11-15: 優先度は **高・中・低** の 3 段階。作成時に必ず指定する(既定値は持たない)
- 2026-11-15: 期限を超過したタスクは、表示で**接頭辞**を付けて示す
- 2026-11-15: 接頭辞は `【超過】-`(ユーザー決定)
- 2026-11-15: 「超過」= 未完了のまま期限の**翌日以降**になっていること。期限当日は超過ではない。完了済みは超過しない
- 2026-11-15: 一覧は**未完了のタスクだけ**を優先度の降順(高→中→低)で表示。同じ優先度では作成日時の古い順(作成日時も同じなら元の順序)
- 2026-11-16: **完了済みタスクは別の「完了済み」一覧で見られ、未完了に戻せる**(ユーザー決定)
- 2026-11-16: 完了済み一覧は**作成日時の新しい順**(ユーザー決定)。同じ作成日時なら元の順序を保つ。完了日時は記録しない(スキーマ変更を避けた)
- 未決定: 繰り返しタスクを扱うか

### 予定
- タイトル、開始日時、終了日時(任意)、場所・メモ(任意)
- 「今日の予定」を表示
- 2026-11-15: **終日予定を扱う**。期間は開始日〜終了日(終了日を含む)。終了日は任意
- 2026-11-15: 時刻付き予定の**終了は任意**。期間は半開区間 [開始, 終了)。終了なし・終了=開始は「瞬間の予定」で開始日にだけ出る
- 2026-11-15: 日をまたぐ予定は**重なる日すべてに出す**(その日の [0:00, 翌0:00) と期間が重なれば出す。翌0:00 ちょうどに終わる予定は翌日に出ない)
- 2026-11-15: その日の一覧は 終日予定 → 時刻付き予定(開始順)
- 2026-11-15: 終了が開始より前の予定、空タイトルの予定は作れない
- 2026-11-15: 時刻はタイムゾーンなしの日本時間として扱う(利用者 1 人のため)
- 2026-11-15: **繰り返し予定は今は扱わない**(単発が完成してから別ブランチで設計)

### メモ
- タイトル、本文、タグ、作成日時・更新日時
- 2026-11-15: **タイトルは必須**、本文は空でもよい
- 2026-11-15: 作成直後は 更新日時 = 作成日時。編集すると更新日時だけ変わる。作成日時より前の時刻では編集できない。編集に失敗したらメモは一切変わらない
- 2026-11-15: **タグを付ける**(1 メモに複数)。前後の空白は除く・空タグ不可・重複は 1 つにまとめる。英字の大文字小文字は区別する(⚠ 確認待ち)
- 2026-11-15: **キーワード検索**: タイトルか本文に含まれるもの。英字の大文字小文字は区別しない。空のキーワードは全件
- 2026-11-15: 一覧は**更新日時の新しい順**。同じ日時は元の順序を保つ
- 2026-11-15: タグの DB 設計は `tags` + 中間テーブル `memo_tags`(多対多)。`docs/db/er.md` 参照
- 2026-11-16: **どのメモからも使われなくなったタグも `tags` に残す**(ユーザー決定)。理由: 次にタグを付けるときの候補に出せるようにするため。たまったタグを消す手段は必要になったら別に作る

### Web 画面(共通)
- 2026-11-16: **ToDo → 予定 → メモの順に 1 機能ずつ作り、最後に「今日」のまとめ画面**(ユーザー決定)。早く実物で振る舞いを確かめるため。ニュースは PDA とは性質が違うので PDA の画面の後
- 2026-11-16: **削除は確認ページを経由する**(ユーザー決定。ToDo・予定・メモ共通)。削除は元に戻せないので誤操作を防ぐ。JavaScript は使わない
- 2026-11-16: 書き込み(POST)の後は一覧へリダイレクトする(Post/Redirect/Get)。再読み込みで二重に登録されるのを防ぐため
- 2026-11-16: DB ファイルは既定で `data/pda.db`。環境変数 `PDA_DB` で変えられる。起動時に `migrate_file` で未適用のマイグレーションを当てる

### ニュース
- 1 日 1 回、設定したフィードから記事を取得
- IT・科学に関係する記事に絞る(ミッションに合わせ、物理・数学と IT が交わる分野を重視する。2026-11-15)
- 記事ごとに日本語要約を作り、配信元・元記事リンクと一緒に表示
- 未決定: 対象フィードの一覧 / 絞り込み方法(キーワード or Claude に判定させる)/ 1 日の要約件数の上限 / 重複記事(同じ話題の別記事)の扱い

## 費用方針
- 2026-11-15: 費用は最小に抑える(ユーザーの生活費に響かないこと)。手段はプロンプト・設計の工夫 + モデル選択
- 概算(1 日 30 記事・まとめて 1 リクエスト、1 ドル = 150 円で換算): Opus 5.5 → 月約 600〜1,200 円 / Haiku 5.5 → 月約 15 円 / Haiku 5.5 + Batch API → 月約 8 円
- 2026-11-15: **当面は Claude API を呼ばず、モック要約で進める**(費用 0 円)。モック要約 = RSS の概要文を先頭から一定文字数で切ったもの。本物への切り替えは `config.py` の設定 1 か所で行えるようにする
- 未決定(本物に切り替えるとき決める): 既定モデル(候補: Haiku 5.5)/ 月の上限額(Console の利用上限にも設定する)
